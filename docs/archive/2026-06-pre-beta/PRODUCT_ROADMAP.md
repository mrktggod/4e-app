Обновлён: 2026-06-18. Ведёт Cowork-наблюдатель.

## Глобальная цель

Лёгкий доступ к персональному AI-ассистенту с личной памятью и прогрессом мышления через:
- задачи и дела
- коммуникации (мессенджеры)
- геолокацию
- персональные данные в целом

## Этапы в порядке приоритета

### Этап 1 — Критические баги и безопасность ← МЫ ЗДЕСЬ
*Соответствует Gate 0 технического roadmap*

**Цель:** приложение не должно иметь дыр, через которые чужой может читать данные пользователей или расходовать AI-бюджет.

Что осталось закрыть:
- [x] KV snapshot (верифицированный backup перед любой миграцией)
- [x] HMAC в production Worker
- [x] Проверка подписи Telegram initData на сервере
- [x] Проверка подписи VK launch params на сервере — verifier deployed, `VK_SECRET_KEY` настроен, invalid/legacy payload hardening deployed; valid VK Mini App smoke-test остаётся ручной проверкой
- [x] CORS ограничить конкретными origins вместо `*`

### Этап 2 — VK-версия + редизайн
*Совместить целесообразно: всё равно трогаем frontend*

**Цель:** VK Mini App работает стабильно и выглядит как продукт, а не прототип. Редизайн делается один раз, не дважды.

Что входит:
- [ ] Завершить VK авторизацию: CORS/launch-param/login hardening опубликованы; после real-device проверок добавлены `edge.4-ai.site`, fast auth screen, login recovery и warm-up первого клика (`vk-auth-warmup-20260620-7`); нужен ручной valid Mini App smoke-test после полного reopen/hard refresh
- [ ] Стабилизировать отображение задач в VK
- [ ] Редизайн: новый frontend из компонентов, не один HTML-файл 5000 строк
- [ ] Все состояния UI: загрузка, ошибка, пустой список, истекшая сессия
  - 2026-06-20: точечный redesign polish опубликован в GitHub Pages (`f3dc86a`): светлая тема главного экрана получила белый фон вместо чёрной подложки, VK host theme больше не перетирает явно выбранную тему, вкладка задачи переименована в `Обсудить задачу`. Архитектурный долг “один HTML-файл” остаётся.
  - 2026-06-20: real VK smoke показал, что VK Mini App грузит `vk.html`, а не `index.html`; runtime redesign слой перенесён в `vk.html` и опубликован (`af531ee`): home redesign, task detail, `Обсудить задачу`, theme toggle. Архитектурный долг “две раздельные frontend-ветки” остаётся.
- [ ] Telegram и VK — единое визуальное решение

### Этап 3 — AI-логика и оптимизация токенов
*Соответствует Gate 5 технического roadmap + новое*

**Цель:** ассистент накапливает знания о пользователе и использует их умно, без лишних расходов.

Что входит:
- [ ] Подключить MiMo API (`mimo-v2.5-pro`) как модель для лёгких задач
  - Классификатор запроса (сам на MiMo): "операция с задачей" → MiMo; "разговор с ассистентом / анализ" → Claude
  - MiMo закрывает: создание/парсинг задач, извлечение даты/времени, простые советы по структуре, классификацию intent
  - Claude остаётся для: советов с учётом истории пользователя, приоритизации всего списка, нюансированных ответов
  - Ожидаемый эффект: ~60–70% запросов уходит на MiMo, расход Claude-токенов снижается кратно
- [ ] Структурированная память: факты, предпочтения, паттерны поведения
- [ ] Summaries вместо хранения полной истории чата
- [ ] Context builder с жёстким token budget
- [ ] Пользователь видит что ассистент "помнит" и может это редактировать

## Технические задачи которые идут параллельно (Gate 1-3)

Эти задачи Codex ведёт как фоновый процесс, не блокируют продуктовые этапы:
- Перенос данных из KV в D1 (нужен до Этапа 3)
- Unified identity (один пользователь = Web + TG + VK)
  - 2026-06-20: legacy read UI опубликован в VK profile; D1/v2 read endpoint `GET /v2/auth/identities` и signed link routes `POST /v2/auth/link-telegram` / `POST /v2/auth/link-vk` задеплоены в staging. Challenge-record foundation, challenge completion route и merge confirmation route для identity conflicts тоже задеплоены в staging: конфликт создаёт pending challenge, повторный signed provider proof помечает его `completed`, а `confirm: true` переносит D1-owned rows на canonical user после preflight. VK frontend получил hidden UI layer для conflict/complete/merge states, но live flow ждёт production D1/v2 auth bridge или cutover. Остались production cutover и unlink/relink policy.
- Cron/Queue для напоминаний вместо Node-процесса
- TypeScript миграция постепенно
