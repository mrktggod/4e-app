# BRIEF-2026-07-30-113 — VK: минимальный паритет профиля (BACK-066E) (P2)

Источник: `docs/tasks/BACK-066-vk-functional-parity-audit-2026-07-22.md`, рекомендованный fix-бриф `BACK-066E`.

### Контекст

VK-профиль (`vk.html`, ~строка 406) показывает только avatar/name/email, identities, theme, support, logout. В основном приложении есть privacy/security/sessions/devices/AI-память — на VK этого нет вообще, даже ссылки нет.

### Задача (минимальный объём, не полный редизайн)

1. Добавь на VK-профиль хотя бы явные ссылки/переходы на privacy и support-поверхности (даже если это переход в основной web-профиль/внешняя ссылка).
2. Если сессии/устройства/AI-память в API уже отдаются безопасно — можно показать read-only сводку; если нет безопасного существующего API — зафиксировать как NEED-CLAUDE, не изобретать новый endpoint.
3. Не трогай auth/session-логику саму по себе.

### Стоп-точки

- Без нового backend-контракта для security/sessions без явного отдельного ревью.
- Без прод-деплоя, без merge в `main`, без live VK-аккаунта.

### Ожидаемый результат

VK-профиль перестаёт быть «глухим» по privacy/support; честный REPORT о том, что добавлено полностью, а что осталось заглушкой/ссылкой наружу.
