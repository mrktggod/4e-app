# BRIEF-2026-07-30-114 — VK AI-чат: честные ошибки вместо общей заглушки (P0)

Разблокирует диагностику `BRIEF-2026-07-23-49-vk-ai-chat-claude-scope` (status: NEED-CLAUDE → в работу). Ниже — ревью и одобренный план из `pm/outbox/REPORT-2026-07-23-49-vk-ai-chat-claude-scope.md`, писать код можно.

### Контекст

`vk.html:1824-1833` (`sendMessage()`) шлёт `POST /anthropic`, парсит `res.json()` **без проверки `res.ok`**, и при любом провале (auth, entitlement, rate-limit, реальная ошибка сервера) показывает один и тот же общий текст «не удалось получить ответ». Тот же паттерн в `vk.html:1769-1783`. Пользователь ВК не может понять, сломан ли ИИ, кончилась ли подписка, или это временный сбой.

### Задача

1. `vk.html:1824-1833` и `vk.html:1769-1783` — проверять `res.ok` **до** парсинга успешного payload.
2. Разделить классы ошибок: не авторизован / запрещено (entitlement) / rate-limit / временная/серверная ошибка / некорректный формат ответа.
3. Добавить локальную диагностику (request-id/status) в debug-вывод без секретов.
4. Retry только для временных сбоев (5xx/network), не для auth/entitlement отказов.
5. `x-token` должен оставаться обязательным везде, где воркер его требует.

### Явные запреты

- Не ослаблять и не убирать `x-token`.
- Не обходить entitlement/payment-гейты.
- Не менять backend auth-контракт.
- Не логировать токены, секреты, персональные данные или полные промпты в отчёте.

### Стоп-точки

- Без прод-деплоя, без merge в `main`, без CAL/VK Pay/цен/платежей/entitlement-рефактора, без секретов, без live VK-аккаунта — только синтетика/моки с редактированными данными.

### Ожидаемый результат

VK AI-чат честно показывает класс ошибки вместо одной общей фразы; smoke на мокнутых исходах (200/401/403/429/500/malformed); `check-cp1251-mojibake` pass; REPORT без секретов/токенов/промптов.
