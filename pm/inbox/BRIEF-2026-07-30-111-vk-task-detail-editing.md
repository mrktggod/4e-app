# BRIEF-2026-07-30-111 — VK: полное редактирование задачи (BACK-066B) (P1)

Источник: `docs/tasks/BACK-066-vk-functional-parity-audit-2026-07-22.md`, рекомендованный fix-бриф `BACK-066B`.

### Контекст

Основной `index.html` поддерживает редактирование title/person/priority/deadline/status/originalMsg через существующий серверный путь. VK-поверхность (`vk.html`) в task detail умеет только просмотр + кнопку done — нельзя поменять срок, приоритет, исполнителя, описание. Это ограничивает VK как полноценный вход в продукт.

### Задача

1. Изучи существующий контракт `x-action:update-task` (использует основной `index.html`, `4e-worker`) — тот же путь, не новый endpoint.
2. Добавь в VK task detail (`vk.html`, ~строка 1434 и окружение) редактирование: title, deadline, status/done, person, description/originalMsg — через тот же `x-action:update-task`.
3. UI можно сделать проще, чем в основном приложении, но должны быть реальные поля ввода/выбора, не заглушки.
4. Не трогай VK Pay/payment/entitlement-логику.

### Стоп-точки

- Не менять backend-контракт `update-task`, только вызывать его с новых полей с VK-стороны.
- Без прод-деплоя, без merge в `main`, без live VK-аккаунта — синтетика/моки для smoke.
- Если для какого-то поля не хватает существующего backend-пути — не изобретать новый endpoint автономно, зафиксировать как отдельный NEED-CLAUDE пункт и остановиться на этом поле.

### Ожидаемый результат

VK task detail позволяет реально поменять срок/приоритет/исполнителя/описание/статус и сохранить через существующий worker-путь; smoke, подтверждающий сохранение; `check-cp1251-mojibake` pass.
