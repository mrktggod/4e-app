# BRIEF-2026-07-30-116 — AI-декомпозиция задачи на этапы (SMART-013) (P2)

Источник: `docs/tasks/SMART-013-ai-task-decomposition.md` (продуктовое решение 2026-07-08). Крупнее остальных пунктов — делать последним, с отдельным ревью перед мержем.

### Контекст

MVP уже решён продуктом: кнопка «Разбить на этапы» внутри существующего блока Чек-лист на `task-detail`. AI анализирует название/описание/срок/приоритет/чек-лист, показывает превью 3-7 этапов, **пользователь явно подтверждает** добавление — AI ничего не пишет без подтверждения. Визуальный ориентир: `docs/tasks/assets/SMART-013-ai-task-decomposition-mockup.png`/`.svg` (в приватном `4pm`, если недоступны — запросить у Юрия).

### UX (кратко)

- Чек-лист пустой → empty-state: «Пока нет этапов / 4 может разложить задачу на понятные шаги / [Разбить на этапы]».
- Чек-лист не пустой → вторичная кнопка «Добавить этапы с AI».
- После нажатия — превью 3-7 этапов с чекбоксами и кнопкой подтверждения. Отмена ничего не меняет в задаче.

### Задача

1. Реализовать кнопку и превью-flow в `task-detail` (`index.html`), используя существующий `/anthropic`-путь — не новый AI-endpoint.
2. Явное подтверждение пользователя обязательно перед записью в чек-лист.
3. Сначала только основной web/PWA MVP; VK/Telegram — отдельным следующим брифом.
4. Учитывай ограничения `BACK-022` (чек-лист) и `BACK-044` (упрощённая карточка) — не делай карточку задачи тяжелее.

### Стоп-точки

- Без авто-записи в задачу без подтверждения пользователя — главное правило брифа.
- Без прод-деплоя, без merge в `main`, без изменений в payment/CAL/entitlement/auth.
- Если понадобится новый backend endpoint — остановиться, зафиксировать как NEED-CLAUDE.

### Ожидаемый результат

Кнопка «Разбить на этапы» работает end-to-end на web/PWA: пустой/непустой чек-лист, превью, подтверждение, отмена без побочных эффектов; smoke; `check-cp1251-mojibake` pass; честный REPORT, если что-то не влезло в одну ночь.
